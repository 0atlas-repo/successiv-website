## What changed

Built the product-led Successiv site end to end, on a branch worktree at
`.worktrees/site-build`.

Discovered mid-task that a previous version already existed at
`/Users/r/Workspaces/0atlas/successiv.com/` — a shipped static site, an Astro
rebuild in progress, official logo SVGs, and a `previews/` folder with three

scratch" to "carry the existing brand forward onto the new positioning".

## Decisions

- Brief wins on content (product-led), existing site wins on brand. The brief
  records a founder lock, so it supersedes the old services framing.
- Astro over Next.js. `docs/BUILD.md` only suggested Next.js, and the existing
  rebuild was already Astro with the tokens done.
- Both themes, not one. Dark is the brand default; light is derived, because
  cyan #5acaed on white is ~1.9:1 and fails AA.
- 1line.ai ships as a fifth product on founder sign-off, with placeholder copy
  that admits it is placeholder.
- Hong Kong was not carried over — the founder left it unchecked.
- The old stat-card work design was dropped. Its own source comment warned
  against invented metrics and we have none.

## Two deploy blockers found and one fixed

- `withastro/action@v4` does not exist. `gh api repos/withastro/action/tags`
  shows the latest is v6.1.3. The workflow would have failed on first push.
  Pinned to v6.
- The repo `0atlas-repo/successiv-website` is **private**. GitHub Pages does not
  serve private repos on free plans. This is not fixable from here — it needs
  either a paid plan or making the repo public. Unresolved.

## Also fixed after review

- 1line.ai's meta description began "Placeholder." — honest on the page, wrong
  in a search snippet. Placeholder products now use the one-liner alone and
  emit `<meta name="robots" content="noindex">`.
- `.reveal` starts at `opacity: 0`, so a visitor with JS disabled saw blank
  sections. Added a `<noscript>` style block that restores them.

## Known inconsistency to settle

The spec and CLAUDE.md say "dark is the brand default", but the CSS lets
`prefers-color-scheme` win, so a visitor on a light OS sees light on first load.
Either is defensible; the docs and the code should agree. Needs a decision.

## Copy fix — NDA framing

"We usually can't name clients" appeared in three places. The founder flagged it
as unprofessional and was right: it apologises for a limitation instead of
stating a standard. Confidentiality is something enterprise buyers pay for, so
it now reads as discretion the reader would also receive.

- /work hero: "Client work stays confidential. The thinking behind it doesn't
  have to." Lede adds "that discretion is part of what you get too".
- Home work section: "Delivery proof, under NDA." / "Client work stays under NDA,
  so we show the shape of the system instead."
- /about: "Client work stays confidential — the same discretion you would get."
